# Bloom — what to run next

**Bloom** is the research artifact for *"Bloom: Designing for LLM-Augmented Behavior Change
Interactions"* (Jörke et al., CHI 2026, [arXiv:2510.05449](https://arxiv.org/abs/2510.05449)): an
iOS app for physical-activity promotion built around an LLM health-coaching chatbot, plus the
field-study data, analysis scripts, and safety/redteaming benchmark that accompany the paper.

`bash .engelbart/setup.sh` has already installed everything below. Nothing else needs installing,
and **no repository file was modified**. Every command is run from the repository root.

* Python 3.12 venv → `.engelbart/venv` (backend + safety deps, analysis deps, Jupyter)
* R 4.4.3 + tidyverse/lme4/lmerTest/nlme/effectsize/pwr → `.engelbart/r`
* `node_modules/` via yarn 3.6.4 (for the documented TypeScript checks only)
* Hanken Grotesk font, so the figures use the paper's typeface

All study data is already committed (`analysis/data/*.csv`, `safety/data/*.csv`, ~2.5 MB total).
**Nothing needs downloading and nothing needs a GPU.** `.engelbart/data/` exists for large
downloads and is git-ignored, but is currently empty because none are required.

Verify at any time with `bash .engelbart/check.sh` (~11 s, exits 0 when the environment is good).

---

## 1. Start here — reproduce the paper's outcome tables

```bash
.engelbart/venv/bin/jupyter nbconvert --to notebook --execute \
  --output-dir .engelbart/out analysis/tables.ipynb
```
Runs `analysis/tables.ipynb` headlessly against the field-study data
(`analysis/data/pre_post.csv`, `daily*.csv`, `weekly.csv`): pre/post means, SDs, and
difference-in-differences for the treatment (LLM) vs. control conditions across the stage-of-change,
IPAQ, satisfaction, motivation, and UX measures. **~3 s.** Output notebook with all tables lands in
`.engelbart/out/tables.ipynb`.

To work through it interactively instead:
```bash
.engelbart/venv/bin/jupyter lab analysis/tables.ipynb
```

## 2. Regenerate the paper's figures

```bash
.engelbart/venv/bin/jupyter nbconvert --to notebook --execute \
  --output-dir .engelbart/out analysis/plots.ipynb
```
Runs `analysis/plots.ipynb`, which **overwrites three tracked PDFs in place** —
`analysis/plots/plan-overview.pdf`, `mindset-arrows.pdf`, `app-usage-summary.pdf`. **~12 s.**
Use `git checkout -- analysis/plots` to restore the originals, or `git diff --stat` to confirm they
match. Bootstrap CIs are seeded (`SEED = 0`) but `resample(..., random_state=None)` is not, so
error bars move slightly between runs.

```bash
cd analysis

cd ..
```

**What this repository is:** the Chrome (MV3) browser extension from the CHI 2026 paper *"Facilitating Proactive and Reactive Guidance for Decision Making on the Web: A Design Probe with WebSeek"* (WXT + React + TypeScript), plus `algorithm_evaluation/` — the 50-task benchmark suite, 6 controlled webpage snapshots, and the LLM task generator used for its technical evaluation. There is no web app to serve here: the extension is loaded unpacked into Chrome, and its FastAPI backend lives in a separate repository.

Setup is already done — `bash .engelbart/setup.sh` installed the 666 npm packages, built the extension into `.output/chrome-mv3/`, created `.env` from `.env.example`, and made a Python 3.11 venv at `.engelbart/venv` with `algorithm_evaluation/requirements.txt`. Nothing here needs a GPU and nothing needs a multi-gigabyte download.

---

```bash

```

## 2. Load the extension in Chrome — the paper's actual artifact (≈10 s + manual steps)

```bash
npm run build                 # rebuild .output/chrome-mv3/ after any source edit (≈7 s)
```

Then, on a desktop machine with **Chrome ≥ 114** (needed for the Side Panel API):

1. open `chrome://extensions`
2. enable **Developer mode**
3. **Load unpacked** → select `<repo>/.output/chrome-mv3`
4. click the WebSeek toolbar icon to open the side panel; enter your OpenRouter key in the ⚙ **Settings** panel

This sandbox has no Chrome and no display, so step 2 onward has to happen on your own machine — copy the repo or the zip from step 4 there.

For live-reload development instead of a one-off build:

```bash
npm run dev                   # long-running watcher; writes .output/chrome-mv3-dev/
```

Load `.output/chrome-mv3-dev` unpacked. (`node patch-manifest.js` is a leftover helper that injects `side_panel` into the *dev* manifest; the current WXT version already emits it, so run it only if your dev manifest is missing the side panel.)


# Mathemyths — what this is and what to run next

**Mathemyths** (CHI 2024, Zhang et al., <https://doi.org/10.1145/3613904.3642647>) is the
source code and prompt library for a *child–AI co-creative storytelling agent*: an
interactive local program that takes turns building a story with a 4–8-year-old while
weaving in quantitative mathematical vocabulary (*equal, sum, half, add, subtract,
estimate*) and asking a comprehension question after each turn. It is a single-user
command-line/desktop application driven by GPT-4 prompts (`src/prompts.py` is the
paper's core artifact), with optional Google Cloud speech-to-text / text-to-speech and
ElevenLabs voice output. There is **no web service, no dataset and no analysis code** in
this repository — the 35-child user study data and the statistics reported in the paper
are not published here, so what you can reproduce is *the system and its prompts*, not
the paper's tables.

Environment created by `bash .engelbart/setup.sh`:

- `.engelbart/venv` — Python 3.10.21 (`requirements.txt` pins `python=3.10.9`), with the
  dependencies the code actually imports.
- `.engelbart/data/portaudio` — PortAudio built from source (1.4 MB download), because
  Debian here has no `portaudio19-dev` and PyPI ships no Linux wheel for PyAudio.
  Nothing else is downloaded; there are no large datasets to fetch.

Use `.engelbart/venv/bin/python` for everything below (no `activate` needed).

`gpt-3.5-turbo-instruct`, change the model names in `src/ask_gpt.py` and `main.py`.
